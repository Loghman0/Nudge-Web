# UI, navigation and workspace update — 27 October 2026

This update follows the user's screenshots and development timing logs. It applies the existing blue Hindsight visual direction consistently and keeps the app unpublished. No database migration or live AI call is part of this batch.

## Delivered

- One original editable vector logo in `public/brand/nudge-mark.svg`, reused by the shared Logo component, landing navigation/footer, app navigation, authentication, favicon, offline screen and social preview. PNG/PWA variants are generated by `scripts/build-brand.mjs`; maskable icons have a safe inset. The prior workspace CSS explicitly hid the old mark; that override is removed.
- Login, signup, password-reset and update-password use the same blue palette and typography as the app. Email/password labels, autofill, password visibility, associated hints, pending states and focused errors are retained. The age/guardian checkbox and related prechecks are removed from login/signup. Authentication does not invent a legal, age or AI-consent record; the separate terms flow remains explicit.
- A compact comparison starts with two visible text fields. Context is a separate step; definitions, saved vocabulary and journal notes are optional disclosures. Back preserves the draft. Mode choices remain available. Missing evidence offers a criteria comparison or a user-chosen outcome rather than fabricated certainty. Source details remain inspectable.
- Context focus changes only when entering that step. Reapplying a saved setting no longer pulls focus away. While saved settings are loading, comparison fields/confirmation are disabled together; confirmation must happen after the reviewed values arrive.
- Shared primary inputs/buttons are at least 48 px tall with 16 px input text. Visible focus, readable light/dark contrast and reduced motion are preserved.
- Discover verifies identity once per page load, runs the two question RPCs concurrently and streams optional pattern checks after the question. Dashboard's independent required and optional reads start together, with a narrower profile projection. Navigation has destination-specific loading UI and pending feedback. Public sign-in/signup links can prefetch.
- Forty-one documentation, historical, evidence and obsolete-helper entries were moved out of the root. Current guides are in `docs/`; history is in `docs/history/`; local evidence, snapshots and one-off scripts are recoverable under ignored `.local/`. The stale root SQL copy is archived; the generated baseline in `supabase/` remains canonical. Build/test runtimes, credentials, source and migrations are retained. Packaging excludes `.local/` and every `audit-*` directory.

## Research and product boundary

See [UX research](UX-RESEARCH-2026-10-27.md) for primary sources, findings, implementation mappings and a first-user research plan. Nudge has no measured abandonment funnel yet. No tracking was added. Reduced form effort is a design hypothesis, not a proven retention increase.

Nudge's purpose is the structured decision–outcome loop. It can preserve user-defined terms and supplied evidence without pretending to know their meaning. It does not independently verify arbitrary facts or guarantee the right answer to every question.

## Verification

Final results: **667 tests passed with no skips**, TypeScript and production build passed, SQL bundles are current, **7 authenticated browser scenarios** and **4 public browser scenarios** passed, and **20 hosted check groups** passed. All three final-run disposable accounts were removed. Light/dark, mobile, keyboard and axe checks passed on the tested screens. The source archive contains 364 inspected entries.

Final local click-to-content samples: Ask 753 ms, Journal 515 ms and Discover 1,082 ms on the first pass; repeat visits were 178 ms, 153 ms and 269 ms respectively. These six samples include automation overhead and background test load; they do not establish a universal latency guarantee or a before/after improvement percentage.

The final run results and package hash are recorded in `.local/evidence/2026-10-27-ux/final-verification.json`. Screenshots and detailed logs are in the same local evidence folder. Current results are also summarized at the top of [Testing](RELEASE-TESTING.md).

An earlier browser pass exposed focus movement during saved-setting review and a selector matching Next.js's inactive retained page. The app focus behavior and the test's visible-page scope were corrected. The first Windows teardown stalled after tests ended; only its two owned Next processes were stopped, and disposable-account cleanup completed. Subsequent browser runs use normal Windows process permissions. A later preflight hit an HTTP 0 transport failure on a disposable circle vote; its cleanup was verified and the bounded run was retried. This remains recorded as an upstream reliability limit, not hidden as a UI success.

The production navigation diagnostic uses a disposable account, desktop Chromium and six clicks across Ask, Journal and Discover. It includes Playwright overhead and local caching; it is not directly comparable with the user's cold development compilation timings. The detailed per-route measurements are in `browser-auth/navigation-timing.json`.

The default test command now caps file-level concurrency at four workers. An unrestricted parallel run ended a PGlite worker unexpectedly after five successful assertions; the isolated file and the bounded final suite are checked separately, without attributing an unreported cause.

No real-user account is a test fixture. The hosted harness deletes only the accounts returned by its own create calls and verifies cleanup. Browser automation and axe checks cover the tested screens, not a complete accessibility certification or actual native-device validation.
